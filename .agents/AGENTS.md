# Workspace Behavioral Rules

## Verification and Status Directives
- **No Premature Declarations**: Never claim a bug, issue, or feature is "fixed", "resolved", or "100% working" without concrete, empirical runtime confirmation or explicit user verification.
- **State Changes Objectively**: Refer to modifications strictly as "changes applied", "candidate patch prepared", or "edits ready for verification".
- **Principal Software Engineer Standard**: Maintain strict technical rigor, provide objective code and resource analysis, and wait for empirical verification before evaluating outcome status.
